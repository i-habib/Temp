How it works

Built for a write-heavy, read-narrow workload.

Metrics workloads look nothing like OLTP: writes are append-only and relentless, reads touch a narrow window of recent time. Quanta’s three subsystems are each shaped around that asymmetry.

Blazing-fast ingest

Durable, low-latency writes that never block your application, with zero configuration required.

Efficient storage

Best-in-class compression keeps your historical data small without sacrificing query performance.

Lightning queries

A smart planner cuts through your data to deliver results in milliseconds, at any scale.

01 — Ingest

Every write lands in two places at once.

A point is appended to an on-disk write-ahead log, which is what makes it durable, and simultaneously inserted into an in-memory memtable, which is what makes it immediately queryable. Neither path waits for the other.

When the memtable reaches 4 MB it is flushed to an immutable block and the corresponding WAL segment is truncated. Because blocks never change after they are written, readers need no locks.

02 — Storage

Columns are stored apart, so they compress together.

A block opens with an 8-byte header, then stores its timestamps delta-of-delta encoded and its values XOR-encoded, and closes with a footer holding the minimum and maximum timestamp in the block.

Keeping the two columns separate is what makes this work: adjacent timestamps differ by a near-constant interval and adjacent values by very little, so each column compresses roughly 11× better than the same points stored row-wise.

03 — Queries

The fastest block is the one you never read.

The planner reads each block’s footer before its body. If the block’s min/max range does not overlap the query window, the entire block is skipped without decoding a single point.

For a typical dashboard query — the last six hours out of a year of retention — that rejects hundreds of blocks and decodes two. 

// a six-hour window over a year of retention
let series = db.query("cpu.user")
    .range(now - 6.hours(), now)
    .rollup(Rollup::Mean, 60.seconds())?;
// 2 blocks decoded, 412 skipped, 1.4 ms
